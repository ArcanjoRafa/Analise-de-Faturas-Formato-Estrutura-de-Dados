## 5) Regras de upload (implementar em `web/servico_upload.py`)

Constante: `PASTA_PDFS = Path(r"C:\Users\rafae\Downloads\pdfs_fatura")`
(com `mkdir(parents=True, exist_ok=True)` para garantir que exista).

Fluxo do processamento de um arquivo enviado:

1. **Validação:** sem arquivo ou extensão diferente de `.pdf` → recusa com HTTP 400
   (mensagem em pt-BR). **Não registra histórico** (não é um PDF).
2. Ler os bytes do arquivo enviado.
3. **Alocação na pasta** (questão de ARQUIVO — nenhum destes casos define status):
   - **Nome não existe** em `PASTA_PDFS` → salvar os bytes com o nome original.
   - **Nome existe + conteúdo idêntico** (SHA-256 dos bytes enviados == hash do arquivo
     existente) → **não salvar de novo**; `nome_arquivo_salvo` = nome do arquivo já
     existente; o fluxo continua normalmente.
   - **Nome existe + conteúdo diferente** → salvar com o próximo sufixo livre:
     `nome (2).pdf`, `nome (3).pdf`, ... — **o original nunca é sobrescrito**.

   ⚠️ **Regra de ouro (correção do dono): estar na pasta NÃO é duplicado.** Nenhuma
   decisão de status sai da pasta — o pipeline da etapa 4 roda SEMPRE.

4. **Pipeline (dentro de try/except):**
   ```python
   fatura = Fatura(str(caminho_final))                      # pode levantar exceção
   with Session() as session:
       resultado, fatura_id = salvar_fatura(fatura, session)
   status = resultado                                        # "SUCESSO" ou "DUPLICADO"
   ```
   - exceção em qualquer ponto → status **FALHA**, mensagem = `str(erro)`.
     O arquivo **permanece** na pasta (todo PDF enviado fica alocado lá).
   - **Único critério de DUPLICADO:** `salvar_fatura` retornar `("DUPLICADO", None)` —
     ou seja, os DADOS EXTRAÍDOS do arquivo (UC + mês de referência) já estarem no
     banco. Nunca marque duplicado por o arquivo já existir na pasta.
   - Comportamento conhecido (não trate como bug): `salvar_fatura` grava cliente/UC/medidor
     em commits intermediários; se a fatura falhar depois, esses registros podem permanecer.
     A página só registra a FALHA com a mensagem — nada de compensação extra.
5. Registrar a linha em `upload_historico`: nome original, nome salvo, `datetime.now()`,
   status, `erro` (só quando FALHA), `fatura_id` (só quando SUCESSO).
6. Retornar JSON para a página.

**Sanitização de nome:** preserve o nome original (é sistema local; nomes têm ç/ã).
Apenas: `Path(nome).name` para remover qualquer componente de caminho, e substituir os
caracteres proibidos no Windows (`\ / : * ? " < > |`) por `_`.

## 6) Endpoints do Flask (`web/app.py`)

```
GET  /                  → renderiza templates/upload.html
GET  /api/historico     → JSON com as linhas: id, nome_pdf, data_upload (ISO), status, erro
                          — ordenadas por data_upload DESC (mais recente primeiro)
POST /api/upload        → multipart com campo "arquivo"; roda o fluxo da seção 5;
                          resposta JSON {"status": ..., "mensagem": ...}
GET  /api/download/<id> → localiza a linha no histórico e serve o arquivo:
                          send_file(PASTA_PDFS / nome_arquivo_salvo, as_attachment=True,
                                    download_name=nome_pdf)
                          404 se a linha não existir ou o arquivo tiver sumido
```

No topo de `app.py`, **antes** dos imports do projeto, o bootstrap de path (faz
`python web/app.py` funcionar a partir da raiz):

```python
import sys, pathlib
sys.path.insert(0, str(pathlib.Path(__file__).resolve().parents[1]))
```

Rodar: `app.run(host="127.0.0.1", port=5000, debug=True)` dentro de
`if __name__ == "__main__":`. Sistema local — sem login, sem CORS externo.

## 7) Front-end (`upload.html` + `upload.css` + `upload.js`) — tudo em pt-BR

Ordem da página:

1. Título: **"Upload de Faturas"**
2. **Campo de upload** — área tracejada com "Arraste o PDF aqui ou clique para procurar":
   - clique abre `<input type="file" accept=".pdf,application/pdf">` (escondido)
   - arrastar destaca a área (dragover) e soltar seleciona o arquivo
   - aceita **um** arquivo por vez; extensão que não seja `.pdf` → mensagem inline de recusa
3. O **nome do arquivo** aparece logo abaixo do campo
4. À direita, um pouco abaixo do nome, dois botões: **[Realizar Upload]** e **[Cancelar]**

   - **Cancelar** esvazia o campo e desativa os botões (não chama o servidor)
   - **Realizar Upload**: trava os botões + "Processando..." → `POST /api/upload` (FormData)
   - resposta: esvazia o campo, atualiza a tabela do histórico e mostra badge/toast colorido
     (SUCESSO verde / DUPLICADO amarelo / FALHA vermelho com a mensagem do erro)
5. **"Histórico de uploads"** — tabela:
   - colunas: `Nome do PDF | Data do upload | Status | Erro | Ação`
   - Status como badge colorido; Erro vazio quando não houver
   - Ação: botão com **ícone de download** → `GET /api/download/<id>`
   - carrega com `GET /api/historico` ao abrir a página e depois de cada upload
   - datas exibidas no formato `dd/mm/aaaa hh:mm` (formatar no JS)

Estilo: CSS próprio, limpo e simples (aplicação local/pessoal). Sem frameworks.
